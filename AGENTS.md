# Maintaining personal-portfolio

Keep one discoverable root, `SKILL.md`, named `personal-portfolio`. Supporting Markdown belongs in `references/` or `examples/` and uses relative links. This is an instruction-only package; add executable code only when a repeated mechanical need justifies it.

Preserve the capability contract: inputs, scope, observable completion, artifacts and honest behavior when access is missing. Keep framework and hosting choices supplied by the receiving project. Do not add personal routes, real account settings, source transcripts or claims of unperformed browser checks.

When changing the workflow, inspect the bundled links, review the scenarios in `references/acceptance.md`, and record which kinds of checks were actually performed. Packaging checks and author walkthroughs are not independent model evaluations.

Before public commits or pushes, follow the owner's release process and privacy scanner. The release must work as a fresh clone with no private overlay. Preserve existing third-party terms if new material is adapted.
