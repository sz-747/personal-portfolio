# Fictional private overlay

Place your real overlay outside the public skill repository. Point to it from the workspace's skill catalogue or agent instructions, and instruct the agent to read it with `personal-portfolio`.

| Setting | Meaning | Fictional example |
|---|---|---|
| `portfolio_repository` | Canonical source selected by workspace routing | `projects/example-portfolio` |
| `design_direction` | Current approved visual direction | Warm paper, generous type, visible card borders |
| `active_references` | Specifically selected design sources and what to borrow | One navigation example and one project-demo layout |
| `preference_sources` | Authorized archive or decision-note scope | The project's approved design-feedback notes |
| `content_inventory` | Where approved articles, project descriptions and media are recorded | `docs/content-inventory.md` in the project |
| `preview_target` | Hosting project and environment | An existing preview environment from workspace routing |
| `decision_note` | Private working record and check evidence | `docs/portfolio-decisions.md` in the project |

An absent overlay does not prevent use. Inspect the repository and the owner's request; ask only for information that affects the next useful step. Missing content, publishing authority or account access must remain explicit. Credentials stay in the receiving workspace's credential store, not this document or the public skill.
